LAB: GET HELP IN RED HAT ENTERPRISE LINUX
Complete Explanation in TXT Format

============================================================
1. PURPOSE OF THIS LAB
============================================================

This lab teaches you how to find and use documentation in Red Hat Enterprise Linux (RHEL).
You will learn how to:

1. Read Linux manual pages using the man command.
2. Search manual pages for commands related to a topic.
3. Convert a manual page into a printable PostScript file.
4. Identify a file's format and inspect its contents.
5. Open PostScript documents using the Evince document viewer.
6. Learn how to print selected pages of a document.
7. Browse documentation stored on the Linux system.
8. Grade and finish the lab.

The main purpose is not simply to print a document. It is to learn how to find help,
understand command options, and work with documentation files in Linux.

IMPORTANT: Perform this assignment on the Red Hat Enterprise Linux workstation
provided by your course or lab environment. Do not perform it in ordinary Windows
Git Bash. Git Bash is not the RHEL workstation and normally does not contain the
Linux Evince application or the lab's /home/student files.

2. BASIC TERMS USED IN THIS LAB
============================================================

RHEL:
Red Hat Enterprise Linux. It is a Linux operating system.

Terminal:
A command-line window where you enter commands.

Shell:
A program that reads and executes commands entered in the terminal.

Bash:
A commonly used Linux shell.

Command:
An instruction that tells the operating system to perform an action.

Documentation:
Information that explains how software, commands, and applications work.

Man page:
A manual page containing information about a Linux command or application.

Standard output:
The normal output produced by a command. Normally, it appears in the terminal.

Redirection (>):
An operator that sends command output into a file instead of displaying it in the
terminal.

Pipe (|):
An operator that sends the output of one command directly to another command.

GUI:
Graphical User Interface. It allows you to interact with applications using windows,
icons, menus, and buttons.

PostScript:
A page-description language used to describe the appearance of text and graphics
on a printed page. It is commonly used as a printable document format.

5. TASK 1 - LEARN HOW TO PREPARE A MAN PAGE FOR PRINTING
============================================================

WHAT IS THE man COMMAND?

The man command displays documentation for Linux commands and applications.
For example:

man passwd

This opens the manual page for the passwd command.

A man page commonly contains:

NAME         The command's name and purpose.
SYNOPSIS     The command's syntax.
DESCRIPTION  A detailed explanation of the command.
OPTIONS      Available options and their meanings.
EXAMPLES     Examples of how to use the command, when provided.

WHAT DOES man man DO?

Command:

man man

The first 'man' runs the manual system. The second 'man' specifies which manual page
to display. Therefore, this command displays the manual for the man command itself.

The assignment asks you to use this manual to find the -t option.

WHAT DOES THE -t OPTION DO?

The -t option prepares a manual page for printing. Its default output is normally
PostScript format.

Example:

man -t bash

This prepares the Bash manual page in a format suitable for printing.

UNDERSTANDING THE PRINTING EXAMPLE:

man -t bash | lpr -Pps

Breakdown:

man       Processes a manual page.
-t        Prepares the manual page for printing.
bash      The manual page to process.
|         Sends the output of the first command to the next command.
lpr       Sends a document to a printer.
-Pps      Selects the printer named 'ps'.

The command prepares the Bash manual page in PostScript format and pipes it to the
printer named ps.

To exit a man page, press the q key.

KEY POINT:
The man -t option prepares a manual page for printing. The default output format
is normally PostScript.

6. TASK 2 - CREATE AND INSPECT A POSTSCRIPT FILE
============================================================

This task creates a PostScript version of the passwd manual page and saves it in
the student user's home directory.

STEP 1: UNDERSTAND OUTPUT REDIRECTION (>)

Normally, a command displays its output in the terminal.
For example:

ls

This lists files and directories in the current directory.

To save command output in a file, use the > operator:

ls > myfiles.txt

This command runs ls and saves its output in myfiles.txt.
If the file does not exist, it is created. If it already exists, its old contents
are overwritten.

STEP 2: CREATE THE POSTSCRIPT FILE

Command:

man -t passwd > passwd.ps

Explanation:

man       Uses the manual system.
-t        Prepares the manual page for printing.
passwd    Specifies the passwd manual page.
>         Redirects the command's output into a file.
passwd.ps The name of the output file.

The command converts the passwd manual page into PostScript format and saves it
as passwd.ps in the current directory. If you are in the student user's home
directory, its full path is:

/home/student/passwd.ps

The .ps extension is commonly used for PostScript files.

STEP 3: CHECK THAT THE FILE EXISTS

Command:

ls -al

Explanation:

ls  Lists directory contents.
-a  Includes hidden files.
-l  Displays detailed information, such as permissions, owner, size, and date.

Look for passwd.ps in the output. Its presence indicates that the file was created.

STEP 4: IDENTIFY THE FILE FORMAT

Command:

file /home/student/passwd.ps

The file command examines a file and reports what type of content it contains.
It does not rely only on the filename extension.

Example output:

/home/student/passwd.ps: PostScript document text conforming DSC level 3.0

Meaning:

PostScript document  The file is a PostScript document.
text                The document contains textual PostScript instructions.
DSC                 Document Structuring Conventions, used to organize PostScript.
level 3.0           The document follows DSC version 3.0.

STEP 5: VIEW THE FILE USING less

Command:

less /home/student/passwd.ps

The less command displays a file one screen at a time. It is useful for viewing
large files without printing all their contents in the terminal at once.

Useful less keys:

Space   Move forward one screen.
b       Move backward one screen.
Enter   Move down one line.
q       Quit less.

The beginning of the file may contain lines similar to:

%!PS-Adobe-3.0
%%Creator: groff version 1.22.3
%%CreationDate: ...
%%DocumentNeededResources: font Times-Roman

Meaning:

%!PS-Adobe-3.0 identifies the document as PostScript.
%%Creator identifies the software that created the document.
%%CreationDate indicates when the document was generated.
%%DocumentNeededResources lists resources, such as fonts, that the document needs.

These header lines help confirm that the file contains PostScript information.
Press q to exit less.

7. TASK 3 - SEARCH FOR COMMANDS RELATED TO POSTSCRIPT
============================================================

You may not know which Linux command can view a PostScript document. Linux lets you
search manual page descriptions using the -k option.

Command:

man -k postscript viewer

Explanation:

man          Opens the manual-page system.
-k           Searches manual page names and descriptions using keywords.
postscript   First search keyword.
viewer       Second search keyword.

The search can return entries that match either keyword. Results depend on which
manual pages are installed on the system.

Some possible results include:

enscript             Converts text files to formats including PostScript.
eps2eps               Processes or converts Encapsulated PostScript files.
evince                GNOME document viewer.
evince-previewer      Shows a printing preview of PostScript and PDF documents.
evince-thumbnailer    Creates thumbnails for PostScript and PDF documents.

WHAT IS EVINCE?

Evince is a graphical document-viewing application. It can display supported
formats, including PDF and PostScript.

The assignment searches for Evince because the next task uses it to open the
passwd.ps file.

8. TASK 4 - OPEN POSTSCRIPT DOCUMENTS USING EVINCE
============================================================

First, read the Evince manual:

man evince

The assignment asks you to find two options:

-w or --preview
Opens the document in preview mode. Preview mode is useful for quickly reviewing
a document before printing it.

-i NUMBER or --page-index=NUMBER
Opens the document at the specified page index. The manual notes that this is the
page index, not necessarily the printed page label.

STEP 1: OPEN THE DOCUMENT IN NORMAL MODE

Command:

evince /home/student/passwd.ps

This opens passwd.ps in the normal Evince document viewer. You can browse pages,
zoom, and use the normal document-viewing features.

STEP 2: OPEN THE DOCUMENT IN PREVIEW MODE

Command:

evince -w /home/student/passwd.ps

Here, -w activates preview mode. The preview interface is useful for reviewing a
document for printing and provides access to printing controls.

STEP 3: OPEN THE DOCUMENT AT PAGE INDEX 3

Command:

evince -i 3 /home/student/passwd.ps

The -i option specifies the page index. The assignment asks you to use the value 3.

Important: Follow the exact command provided by the lab. A page index and a printed
page label are not always the same thing.

Close the document viewer when you have finished checking each mode.

SUMMARY:

evince /home/student/passwd.ps       Opens the document normally.
evince -w /home/student/passwd.ps    Opens the document in preview mode.
evince -i 3 /home/student/passwd.ps  Opens the document at page index 3.

9. TASK 5 - LEARN HOW TO PRINT SPECIFIC PAGES
============================================================

The lp command sends documents to a printer.

Example:

lp document.pdf

This sends document.pdf to the default printer.

A default printer is the printer that the system selects when you do not specify
another printer.

STEP 1: READ THE lp MANUAL

Command:

man lp

Find the -P option. It specifies which pages of a document should be printed.

Examples of page selections:

-P 2       Prints only page 2.
-P 2-3     Prints pages 2 through 3.
-P 1,3     Prints pages 1 and 3.
-P 1,3-5   Prints page 1 and pages 3 through 5.

STEP 2: UNDERSTAND THE REQUIRED COMMAND

The assignment asks you to learn the one-command syntax for printing only pages 2
and 3 of passwd.ps. It specifically says not to execute the command because a
printer is not available.

Required command:

lp passwd.ps -P 2-3

Explanation:

lp          Sends a document to a printer.
passwd.ps   The document to print.
-P          Selects the pages to print.
2-3         Selects pages 2 and 3.

IMPORTANT DIFFERENCE BETWEEN lpr AND lp OPTIONS:

In this example from Task 1:

lpr -Pps

-Pps selects a printer named ps.

In this Task 5 example:

lp passwd.ps -P 2-3

-P 2-3 selects the pages to print.

The same-looking option can have a different meaning in different commands.

Do not execute the lp passwd.ps -P 2-3 command for this assignment. Only learn
and record its syntax.

10. TASK 6 - BROWSE SYSTEM DOCUMENTATION USING FIREFOX
============================================================

Linux stores documentation for many installed software packages in:

/usr/share/doc

Understanding this path:

/       Root directory of the Linux filesystem.
usr     Contains many system programs and resources.
share   Contains shared resources.
doc     Contains documentation.

STEP 1: OPEN THE DOCUMENTATION DIRECTORY

Command:

firefox /usr/share/doc

This launches Firefox and asks it to open the local documentation directory.
Firefox can browse local files and folders as well as websites.

STEP 2: BROWSE THE man-db DIRECTORY

Inside /usr/share/doc:

1. Find the man-db directory.
2. Open it.
3. Review the documentation files provided there.
4. Open the text version of a manual and read it.
5. Close the text document.
6. Open the PostScript version, if provided.
7. Observe that the system's configured document viewer, such as Evince, opens it.
8. Close the document viewer when finished.

WHAT IS man-db?

man-db is a software package that provides and manages the manual-page system.
It supports access to command documentation through commands such as:

man ls

STEP 3: BROWSE THE kexec-tools DIRECTORY

Return to /usr/share/doc and find the kexec-tools directory.
Open it and locate this file:

kexec-kdump-howto.txt

Open and read the file as requested by the assignment.

WHAT IS kexec-tools?

kexec-tools provides utilities related to loading another Linux kernel from an
already running system. It is also associated with crash-dump functionality.

WHAT IS KDUMP?

Kdump is a Linux crash-dump mechanism. When a kernel crash occurs, kdump can help
capture information that administrators or developers can use to investigate the
problem.

WHAT IS /etc/sysconfig?

/etc/sysconfig is a directory that contains configuration files used by various
system services and applications. The kexec-kdump-howto.txt document describes
important configuration settings stored there.

For this assignment, you only need to read the documentation. Do not change files
inside /etc/sysconfig.

After reviewing the file, close the document and Firefox.

15. TROUBLESHOOTING: 'evince: command not found' IN GIT BASH
============================================================

Example of the error:

ashis@Dronzer MINGW64 ~
$ evince /home/student/passwd.ps
bash: evince: command not found

WHY DOES THIS HAPPEN?

MINGW64 in the prompt indicates that the terminal is Git Bash on Windows. It is
not the Red Hat Enterprise Linux workstation used by this lab.

There are two separate problems:

1. Evince is a Linux graphical application and is not normally installed in
   Windows Git Bash.
2. /home/student/passwd.ps is a path in the RHEL lab environment. It will not
   automatically exist in the Git Bash environment on Windows.

WHAT SHOULD YOU DO?

Open the RHEL workstation provided by your Red Hat training environment or the
Linux virtual machine used for the course. Log in as student on workstation.
The prompt should resemble:

[student@workstation ~]$

Then start the lab and perform the assignment there:

lab start help-review

Create the file:

man -t passwd > passwd.ps

Open it using Evince:

evince /home/student/passwd.ps

If you are using a Linux virtual machine and Evince is genuinely missing there,
check the lab instructions or ask the lab administrator whether the required
package and graphical desktop are installed. Do not assume that installing
Evince in Git Bash will give you access to the RHEL lab's files or lab commands.

Pressing Ctrl+C in the Git Bash terminal only interrupts the current command. It
does not damage the RHEL lab or the computer.
