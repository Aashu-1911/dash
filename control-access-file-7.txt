LAB: CONTROL ACCESS TO FILES
============================================================

1. INTRODUCTION
---------------

In Linux, file permissions control who can read, modify, and execute files and directories.

Linux provides a permission system that allows administrators to:

1. Control access to files and directories.
2. Allow multiple users to work together.
3. Assign group ownership to files.
4. Prevent unauthorized users from accessing confidential files.
5. Automatically assign group ownership to newly created files.
6. Set default permissions using umask.

In this practical, we create a shared directory named:

/home/techdocs

Users belonging to the techdocs group can create and access files inside this directory.

Users outside the techdocs group cannot access the directory.

We also configure the SETGID permission and change the default umask.

3. IMPORTANT LINUX FILE PERMISSIONS
------------------------------------------------------------

Linux provides three basic permissions:

A. READ (r)
   Numeric value: 4

   For files:
   Allows users to read file contents.

   For directories:
   Allows users to list the directory contents.

B. WRITE (w)
   Numeric value: 2

   For files:
   Allows users to modify file contents.

   For directories:
   Allows users to create, delete, and rename entries inside
   the directory (subject to other restrictions).

C. EXECUTE (x)
   Numeric value: 1

   For files:
   Allows users to execute the file as a program or script.

   For directories:
   Allows users to enter the directory and access its contents
   when they know the required filenames.

IMPORTANT:

For directories, execute permission is particularly important.
Without execute permission, users cannot normally access files
inside that directory, even if they know the filenames.

------------------------------------------------------------
4. THREE CATEGORIES OF LINUX PERMISSIONS
------------------------------------------------------------

Linux permissions are divided into three categories.

1. USER (u)
   The owner of the file or directory.

2. GROUP (g)
   Users belonging to the group assigned to the file or directory.

3. OTHER (o)
   All remaining users who are neither the owner nor members
   of the assigned group.

Example:

-rwxr-xr--

Breakdown:

-    File type
rwx  User permissions
r-x  Group permissions
r--  Other permissions

Numeric representation:

User  = 7 (4+2+1)
Group = 5 (4+0+1)
Other = 4 (4+0+0)

Therefore:

rwxr-xr-- = 754

------------------------------------------------------------
5. UNDERSTANDING THE PERMISSION NUMBERS
------------------------------------------------------------

Permission values:

r = 4
w = 2
x = 1

Common combinations:

0 = ---
1 = --x
2 = -w-
3 = -wx
4 = r--
5 = r-x
6 = rw-
7 = rwx

Examples:

chmod 755 file.txt

User  = rwx
Group = r-x
Other = r-x

chmod 700 file.txt

User  = rwx
Group = ---
Other = ---

chmod 770 directory

User  = rwx
Group = rwx
Other = ---

chmod 644 file.txt

User  = rw-
Group = r--
Other = r--

7. UNDERSTANDING GROUP OWNERSHIP
------------------------------------------------------------

Linux allows multiple users to belong to the same group.

Example:

Group: techdocs

Members:
- tech1
- tech2

Both users belong to the techdocs group.

This allows them to share files and directories.

To check the groups of a user:

groups tech1

To display detailed user and group information:

id tech1

Example output:

uid=1001(tech1) gid=1001(tech1) groups=1001(tech1),2001(techdocs)

Explanation:

uid = User ID
gid = Primary Group ID
groups = All groups the user belongs to

IMPORTANT:

Primary group:
The main group assigned to a user.

Supplementary group:
An additional group to which a user belongs.

A user can belong to multiple supplementary groups.

The tech1 and tech2 users are members of the techdocs group.

The database1 user is not a member of the techdocs group.

------------------------------------------------------------
8. UNDERSTANDING SETGID PERMISSION
------------------------------------------------------------

SETGID stands for Set Group ID.

Numeric value:

2

SETGID has different behavior depending on whether it is
applied to a file or a directory.

A. SETGID ON EXECUTABLE FILES

When applied to an executable file, the process runs with
the effective group ID of the file's group.

B. SETGID ON DIRECTORIES

When applied to a directory, newly created files and
subdirectories inherit the directory's group ownership.

This is particularly useful for collaborative directories.

Example:

chmod 2770 /home/techdocs

Here:

2 = SETGID
7 = Owner permissions (rwx)
7 = Group permissions (rwx)
0 = Other permissions (---)

Result:

drwxrws---

Explanation:

d = Directory
rwx = Owner has read, write and execute permissions
rws = Group has read, write and execute permissions
--- = Other users have no permissions

Notice the letter s.

The s indicates that SETGID is enabled along with the
group execute permission.

IMPORTANT:

Without SETGID:

A file created by tech1 generally receives tech1's
primary group as its group ownership.

With SETGID:

A file created inside /home/techdocs inherits the
techdocs group.

Example:

tech1 creates techdoc1.txt.

Owner = tech1
Group = techdocs

tech2 creates techdoc2.txt.

Owner = tech2
Group = techdocs

Both files automatically belong to the techdocs group.

------------------------------------------------------------
9. UNDERSTANDING SPECIAL PERMISSIONS
------------------------------------------------------------

Linux has three special permissions.

1. SETUID (4)

   Used mainly on executable files.

   The program runs with the effective user ID of the
   file owner.

2. SETGID (2)

   On executable files, it affects the effective group ID.

   On directories, new files and directories inherit the
   parent directory's group ownership.

3. STICKY BIT (1)

   Commonly used on shared directories.

   It restricts deletion and renaming of files so that
   generally only the file owner, directory owner, or root
   can delete or rename an entry.

Example:

chmod 1777 /shared

This creates a directory with the sticky bit and full
permissions for everyone.

Common example:

/tmp

The /tmp directory commonly uses sticky-bit permissions.

------------------------------------------------------------
10. UNDERSTANDING UMASK
------------------------------------------------------------

UMASK stands for User File Creation Mode Mask.

It controls which permissions are removed from the default
permissions when a user creates new files and directories.

It does not directly assign permissions.

Default starting permissions:

Files       = 666 (rw-rw-rw-)
Directories = 777 (rwxrwxrwx)

UMASK removes permissions from these defaults.

Example:

umask 0022

For files:

666 - masked permissions = 644

Final permissions:

rw-r--r--

For directories:

777 - masked permissions = 755

Final permissions:

rwxr-xr-x

Another example:

umask 0007

For files:

666 with mask 007 = 660

Final permissions:

rw-rw----

For directories:

777 with mask 007 = 770

Final permissions:

rwxrwx---

Explanation of umask 0007:

First digit = Special permission mask position
Second digit = User mask
Third digit = Group mask
Fourth digit = Other mask

The last digit 7 means:

Other users lose:
Read  = 4
Write = 2
Execute = 1

Total = 7

Therefore, other users receive no permissions on newly
created files or directories.

IMPORTANT:

Umask 0007 does not automatically grant execute permission
to newly created regular files.

Regular files normally start with 666, so their resulting
permissions are 660.

Directories start with 777, so their resulting permissions
are 770.

------------------------------------------------------------
11. DIFFERENCE BETWEEN CHMOD AND UMASK
------------------------------------------------------------

CHMOD:

Changes the permissions of an existing file or directory.

Example:

chmod 770 /home/techdocs

UMASK:

Controls default permissions of newly created files and
directories.

Example:

umask 0007

Difference:

chmod changes existing permissions.

umask controls the permissions assigned during creation.

12. UNDERSTANDING /etc/login.defs
------------------------------------------------------------

Location:

/etc/login.defs

Purpose:

This configuration file contains default settings related
to user login and account management.

It can contain settings such as:

- Password aging policies.
- Default user configuration.
- Login-related settings.
- Default UMASK.

In this practical, we modify the UMASK setting.

To view the file:

cat /etc/login.defs

To search for UMASK:

grep UMASK /etc/login.defs

Example configuration:

UMASK 007

This specifies the default umask for login-related
user account configuration.

IMPORTANT:

/etc/login.defs is not a universal live configuration
mechanism for every shell or every user session.

The actual umask can also be configured by PAM,
shell startup files, or system-specific login mechanisms.

In this lab, the expected behavior is that a fresh
student login session receives umask 0007.

14. IMPORTANT DIFFERENCE: DIRECTORY PERMISSIONS VS FILE
PERMISSIONS
------------------------------------------------------------

Directory permissions:

r = List directory contents.
w = Create, delete or rename directory entries.
x = Enter and access the directory.

File permissions:

r = Read file contents.
w = Modify file contents.
x = Execute the file.

IMPORTANT CONCEPT:

A user may have permission to read a file but still be
unable to access it if the user does not have execute
permission on one of its parent directories.

Similarly, write permission on a directory does not
automatically mean write permission on every file inside it.

------------------------------------------------------------
15. IMPORTANT DIFFERENCE: SETGID VS SUPPLEMENTARY GROUP
------------------------------------------------------------

SUPPLEMENTARY GROUP:

Determines which additional groups a user belongs to.

Example:

tech1 belongs to techdocs.

SETGID:

Ensures that files and subdirectories created inside
a SETGID directory inherit that directory's group.

Example:

chmod 2770 /home/techdocs

Both concepts work together:

1. tech1 and tech2 belong to techdocs.
2. The directory is assigned to techdocs.
3. SETGID is enabled.
4. Newly created files inherit techdocs group ownership.

------------------------------------------------------------
16. IMPORTANT DIFFERENCE: CHOWN VS CHMOD
------------------------------------------------------------

CHOWN:

Changes file ownership.

Example:

chown tech1:techdocs file.txt

Owner = tech1
Group = techdocs

CHMOD:

Changes file permissions.

Example:

chmod 640 file.txt

Owner = rw-
Group = r--
Other = ---

Remember:

chown = Ownership
chmod = Permissions

18. COMMON ERRORS AND THEIR REASONS
------------------------------------------------------------

ERROR 1:

Permission denied while creating a file.

Reason:

The user does not have write and execute permissions
on the target directory.

Solution:

Check permissions:

ls -ld /home/techdocs

For this practical:

chmod 2770 /home/techdocs

ERROR 2:

Permission denied while reading a file.

Possible reasons:

1. The user lacks read permission on the file.
2. The user lacks execute permission on a parent directory.
3. The user is not in the appropriate group.

Solution:

Check:

id username
ls -l filename
ls -ld /home/techdocs

ERROR 3:

New files have the wrong group ownership.

Reason:

SETGID is not enabled on the parent directory, or the
directory has the wrong group ownership.

Solution:

chown :techdocs /home/techdocs

chmod 2770 /home/techdocs

ERROR 4:

UMASK still shows 0022.

Possible reasons:

1. The current session was started before the configuration
   was changed.
2. Another login configuration overrides the setting.
3. The login mechanism does not apply the setting from
   /etc/login.defs.

Solution:

Open a fresh login session and check again.

If necessary, inspect the system's PAM and shell startup
configuration.
