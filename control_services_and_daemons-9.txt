2. UNDERSTANDING SERVICES AND DAEMONS
============================================================

WHAT IS A SERVICE?

A service is a program that runs in the background and provides functionality to the operating system or other applications.

Examples:

- sshd: Allows remote SSH connections.
- httpd: Runs an Apache web server.
- rsyslog: Handles system logging.
- firewalld: Manages the firewall.
- crond: Executes scheduled tasks.
- psacct: Maintains process accounting information.

WHAT IS A DAEMON?

A daemon is a background process that runs without requiring direct interaction from the user.

Examples:
- sshd is an SSH daemon.
- httpd is an HTTP server daemon.
- crond is a scheduling daemon.

Remember:
- Service: A background system functionality that can be managed.
- Daemon: A background process that provides that functionality.

WHAT IS SYSTEMD?

systemd is the system and service manager used by modern RHEL systems.

It is responsible for:
- Starting services during boot.
- Stopping services.
- Managing background processes.
- Managing system startup.
- Monitoring service status.
- Managing dependencies between services.

We communicate with systemd using the systemctl command.

============================================================
3. IMPORTANT CONCEPTS: START VS ENABLE
============================================================

START A SERVICE

Command:
systemctl start httpd

Meaning:
Starts the service immediately.

Starting a service does not automatically configure it to start after the next reboot.

ENABLE A SERVICE

Command:
systemctl enable httpd

Meaning:
Configures the service to start automatically during system boot.

Enabling a service does not necessarily start it immediately.

DIFFERENCE BETWEEN START AND ENABLE

- systemctl start service: Starts the service immediately.
- systemctl stop service: Stops the service immediately.
- systemctl enable service: Enables automatic startup at boot.
- systemctl disable service: Disables automatic startup at boot.

FOUR POSSIBLE SERVICE STATES

1. Active + Enabled:
   The service is running now and is configured to start at boot.

2. Active + Disabled:
   The service is running now but is not configured to start automatically at boot.

3. Inactive + Enabled:
   The service is stopped now but is configured to start at boot.

4. Inactive + Disabled:
   The service is stopped and is not configured to start automatically.

Important:
Running status and boot configuration are independent. A service can be running while disabled, or stopped while enabled.

4. SERVICES USED IN THIS LAB
============================================================

A. psacct

psacct stands for Process Accounting.

It is used to maintain information about processes executed on a Linux system.

It helps administrators track process activity and resource usage.

Examples of information it can help track:
- Which commands were executed.
- Which users executed commands.
- How much CPU time processes consumed.

B. rsyslog

rsyslog is a system logging service.

It collects and manages log messages generated by:
- Linux kernel.
- System services.
- Applications.
- Other system components.

System log directory:
/var/log/

Some important log files:

- /var/log/messages: General system messages.
- /var/log/secure: Authentication and security messages.
- /var/log/cron: Cron-related messages.

Important:
Stopping rsyslog stops its logging service. It does not stop the entire Linux system or necessarily stop every form of logging.

Explanation:

- student: Username.

Before connecting, the prompt may look like:

After connecting, it should look like:
[student@serverb ~]$

You are now working on the remote server.

WHAT IS SSH?

SSH stands for Secure Shell. It allows you to securely connect to another computer over a network and execute commands remotely.

General syntax:
ssh username@hostname

Example:
ssh root@192.168.1.10

STEP 3: SWITCH TO ROOT USER

Command:
sudo -i

Explanation:
- sudo: Runs commands with elevated privileges.
- -i: Starts an interactive login shell as the target user, which is root by default.

After executing this command, the prompt should look like:
[root@serverb ~]#

You are now the root user.

WHY DO WE NEED ROOT?

Managing system services generally requires administrative privileges.

For example:
systemctl start psacct

A normal user generally cannot start or stop system services without sufficient permissions.

Remember:
- $ usually indicates a normal user's shell prompt.
- # indicates a root shell prompt.

6. PRACTICAL EXECUTION: STEP-BY-STEP EXPLANATION
============================================================

TASK 1: CHECK THE STATUS OF PSACCT

Command:
systemctl status psacct

This command displays detailed information about the service.

Example output:

psacct.service - Kernel process accounting
Loaded: loaded (/usr/lib/systemd/system/psacct.service; disabled)
Active: inactive (dead)

Understanding the output:

- psacct.service: Service name.
- Loaded: loaded: The service unit file is available.
- disabled: Not configured to start automatically.
- Active: inactive: The service is currently stopped.
- dead: No active service process is running.

In this lab, the initial state is:
- Service is inactive.
- Service is disabled.

TASK 2: START PSACCT SERVICE

Command:
systemctl start psacct

This starts the psacct service immediately.

VERIFY THAT IT IS RUNNING

Command:
systemctl is-active psacct

Expected output:
active

WHAT IS IS-ACTIVE?

is-active checks whether the service is currently running.

Possible outputs include:
- active: Service is running.
- inactive: Service is stopped.
- failed: Service failed.
- activating: Service is starting.

TASK 3: ENABLE PSACCT SERVICE

Command:
systemctl enable psacct

This configures psacct to start automatically during system boot.

Example output:
Created symlink /etc/systemd/system/multi-user.target.wants/psacct.service -> /usr/lib/systemd/system/psacct.service.

WHAT IS A SYMLINK?

A symlink means symbolic link. It is similar to a shortcut in Windows.

When you enable a service, systemd generally creates a symbolic link in the appropriate target's .wants directory.

This tells systemd to start the service when the associated target is reached.

VERIFY THE SERVICE

Command:
systemctl is-enabled psacct

Expected output:
enabled

WHAT IS IS-ENABLED?

is-enabled checks whether a service is configured for automatic startup.

Possible outputs:
- enabled: Configured to start at boot.
- disabled: Not configured to start at boot.
- static: Cannot be enabled directly in the normal way.
- masked: Prevented from being started.

IMPORTANT DIFFERENCE

systemctl is-active psacct
Checks whether the service is running now.

systemctl is-enabled psacct
Checks whether the service is configured to start automatically at boot.

7. STOP THE RSYSLOG SERVICE
============================================================

TASK 1: CHECK RSYSLOG STATUS

Command:
systemctl status rsyslog

Example output:

rsyslog.service - System Logging Service
Loaded: loaded (/usr/lib/systemd/system/rsyslog.service; enabled)
Active: active (running)

Understanding the output:
- Loaded: loaded: Service configuration file is available.
- enabled: Configured to start automatically at boot.
- Active: active (running): Currently running.

The lab asks us to stop this service.

TASK 2: STOP RSYSLOG

Command:
systemctl stop rsyslog

This stops the service immediately.

VERIFY

Command:
systemctl is-active rsyslog

Expected output:
inactive

This confirms that the service is no longer running.

Remember:
Stopping a service does not disable it. If you reboot now, an enabled service can start automatically again.

============================================================
8. DISABLE RSYSLOG SERVICE
============================================================

The next task is to prevent rsyslog from automatically starting during system boot.

Command:
systemctl disable rsyslog

Example output:
Removed /etc/systemd/system/multi-user.target.wants/rsyslog.service.

Explanation:
- disable: Removes the automatic startup configuration.
- The symbolic link is removed from the appropriate systemd target directory.

VERIFY

Command:
systemctl is-enabled rsyslog

Expected output:
disabled

Now the service is:
- Stopped.
- Disabled.

This means it is not currently running and is not configured to start automatically at boot.

9. REBOOT THE SERVERB MACHINE
============================================================

Command:
systemctl reboot

This restarts the Linux machine.

During reboot:
- The system starts the shutdown process.
- Running services are stopped as part of shutdown.
- The machine restarts.
- systemd starts services according to their boot configurations.

You may see:
Connection to serverb closed by remote host.

This is normal.

Why?
You were connected to serverb using SSH. When the server reboots, the SSH connection is disconnected.

You return to the workstation prompt:
[student@workstation ~]$

This does not mean your SSH command failed.

12. IMPORTANT SYSTEMCTL COMMANDS – QUICK REVISION
============================================================

systemctl status sshd
Displays detailed service status.

systemctl start sshd
Starts a service.

systemctl stop sshd
Stops a service.

systemctl restart sshd
Restarts a service.

systemctl reload sshd
Reloads service configuration if supported.

systemctl enable sshd
Enables automatic startup.

systemctl disable sshd
Disables automatic startup.

systemctl is-active sshd
Checks whether the service is running.

systemctl is-enabled sshd
Checks whether the service is enabled for boot.

systemctl enable --now sshd
Enables and starts the service.

systemctl disable --now sshd
Disables and stops the service.

systemctl reboot
Restarts the system.

systemctl poweroff
Shuts down the system.

systemctl list-units --type=service
Lists loaded service units.

systemctl list-unit-files --type=service
Lists installed service unit files.

TWO USEFUL ADDITIONAL COMMANDS

ENABLE AND START TOGETHER

Command:
systemctl enable --now psacct

This performs two operations:
1. Enables the service for boot.
2. Starts the service immediately.

DISABLE AND STOP TOGETHER

Command:
systemctl disable --now rsyslog

This performs two operations:
1. Disables automatic startup.
2. Stops the service immediately.

15. IMPORTANT VIVA QUESTIONS AND ANSWERS
============================================================

Q1. What is systemd?
Answer: systemd is the system and service manager responsible for managing services and system startup in modern Linux distributions.

Q2. What is systemctl?
Answer: systemctl is a command-line utility used to manage systemd services and other systemd units.

Q3. What is the difference between start and enable?
Answer:
- start runs a service immediately.
- enable configures a service to start automatically during boot.

Q4. What is the difference between stop and disable?
Answer:
- stop terminates a currently running service.
- disable prevents automatic startup during boot.

Q5. What is a daemon?
Answer: A daemon is a background process that provides services without requiring direct user interaction.

Q6. What is SSH?
Answer: SSH stands for Secure Shell. It provides secure remote access to another computer.

Q7. What is the purpose of psacct?
Answer: It provides process accounting information to track executed processes and their resource usage.

Q8. What is the purpose of rsyslog?
Answer: It collects and manages system log messages.

Q9. What is the difference between is-active and is-enabled?
Answer:
- is-active checks the current running state.
- is-enabled checks the automatic startup configuration.

Q10. What does systemctl reboot do?
Answer: It restarts the Linux machine.

Q11. What is a symbolic link?
Answer: A symbolic link is a special file that points to another file or directory, similar to a shortcut in Windows.

Q12. Can a disabled service be started manually?
Answer: Yes. Use:
systemctl start service_name

Disabling a service only means it is not configured for automatic startup.

Q13. Can an enabled service be stopped?
Answer: Yes. Use:
systemctl stop service_name

It remains enabled and can start again during the next boot.
