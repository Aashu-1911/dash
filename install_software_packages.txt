LAB: INSTALL AND UPDATE SOFTWARE PACKAGES

1. OBJECTIVE OF THIS LAB
------------------------

The purpose of this lab is to learn how to manage software packages in Red Hat Enterprise Linux (RHEL).

In Linux, software is distributed in the form of packages. We use package management tools to install, update, upgrade, and remove software.

In this practical, we will learn:

1. How to configure a software repository.
2. How to list available software packages.
3. How to install packages using DNF.
4. How to remove installed packages.
5. How to inspect RPM package information.
6. How to install an RPM package manually.
7. How to verify whether a package is installed.

------------------------------------------------------------
2. IMPORTANT CONCEPTS
------------------------------------------------------------

A. WHAT IS A SOFTWARE PACKAGE?

A software package is a collection of files required to install and run a particular application or software.

For example:
- cups: Printing service software.
- rht-system: RHCSA practice package.
- httpd: Apache web server.
- vim: Text editor.

Linux packages generally contain:
- Application files.
- Configuration files.
- Libraries.
- Documentation.
- Installation scripts.

B. WHAT IS A PACKAGE MANAGER?

A package manager is a tool that helps us install, update, upgrade, and remove software.

In RHEL 9, the primary package management tool is DNF.

DNF stands for Dandified YUM.

Common package management commands:

dnf install package_name
    Installs a package.

dnf remove package_name
    Removes a package.

dnf update
    Updates installed packages.

dnf list
    Lists packages.

dnf search keyword
    Searches for packages.

dnf info package_name
    Displays package information.

C. WHAT IS A SOFTWARE REPOSITORY?

A software repository is a location where Linux packages are stored.

A repository can be hosted on:
- An HTTP server.
- An HTTPS server.
- An FTP server.
- A local directory.
- A network server.

DNF uses repositories to find and download software packages.

Example repository URL:

http://content.example.com/rhel9.3/x86_64/rhcsa-practice/errata

D. WHAT IS AN RPM PACKAGE?

RPM stands for Red Hat Package Manager.

An RPM file is a package file used by RHEL-based Linux distributions.

Example:

rhcsa-script-1.0.0-1.noarch.rpm

Its filename contains:

rhcsa-script = Package name
1.0.0 = Version
1 = Release number
noarch = Architecture independent
rpm = Package file format

Difference between DNF and RPM:

DNF:
- Installs packages from repositories or local RPM files.
- Automatically handles dependencies.
- Can update packages.
- Can remove packages.

RPM:
- Works directly with RPM package files.
- Can inspect package information.
- Can install and remove RPM packages.
- Does not automatically resolve dependencies like DNF.

IMPORTANT:
For normal package installation, DNF is generally preferred because it handles dependencies automatically.

5. CONFIGURE A SOFTWARE REPOSITORY
------------------------------------------------------------

TASK:

Create a repository named errata on serverb.

Repository configuration file:

/etc/yum.repos.d/errata.repo

A. UNDERSTANDING THE REPOSITORY DIRECTORY

Directory:

/etc/yum.repos.d/

Explanation:

This directory contains repository configuration files used by DNF.

These files generally have the .repo extension.

Example:

rhel.repo
appstream.repo
baseos.repo
errata.repo

B. CREATE THE REPOSITORY FILE

Command:

vim /etc/yum.repos.d/errata.repo

Explanation:

This opens the Vim editor and allows us to create or edit the repository configuration file.

Add the following content:

[errata]
name=Red Hat Updates
baseurl=http://content.example.com/rhel9.3/x86_64/rhcsa-practice/errata
enabled=1
gpgcheck=0

Save and exit:

Press ESC
Type :wq
Press ENTER

C. UNDERSTANDING EACH CONFIGURATION OPTION

1. [errata]

This is the repository ID.

It uniquely identifies the repository.

2. name=Red Hat Updates

This specifies the human-readable name of the repository.

3. baseurl=

This specifies the location from where DNF downloads packages.

Here, packages are stored on an HTTP server.

4. enabled=1

This enables the repository.

Values:

enabled=1 means repository is enabled.

enabled=0 means repository is disabled.

5. gpgcheck=0

This disables GPG signature verification for packages from this repository.

GPG signatures are used to verify package authenticity and integrity.

Values:

gpgcheck=1 means verify GPG signatures.

gpgcheck=0 means do not verify GPG signatures.

IMPORTANT:

This lab specifically requires gpgcheck=0.

In production environments, package signature verification should generally remain enabled.

Removing the CUPS package helps achieve this requirement.

Explanation:

This command installs the local RPM package using DNF.

sudo:
Runs the command with administrative privileges.

dnf:
Package manager.

install:
Installs the specified package.

rhcsa-script-1.0.0-1.noarch.rpm:
The local RPM package file.

Why use DNF instead of RPM?

DNF can automatically resolve and install required dependencies from configured repositories.

Explanation:

Understanding the command:

rpm = RPM package management command.

IMPORTANT DIFFERENCE:

============================================================
15. DIFFERENCE BETWEEN DNF AND RPM
============================================================

DNF:

1. Works with configured software repositories.
2. Can install packages from repositories.
3. Can install local RPM files.
4. Automatically resolves dependencies.
5. Can update and remove packages.
6. Recommended for normal package management.

RPM:

1. Works directly with RPM package files.
2. Can query package information.
3. Can install RPM files.
4. Can remove installed RPM packages.
5. Does not automatically resolve dependencies.

Example:

dnf install httpd

Installs Apache web server and handles dependencies.

rpm -ivh httpd.rpm

Attempts to install the specified RPM file directly.

Common UNIX Printing System, used for printing services.

Secure Shell, used to connect to remote systems securely.
